# nexus-fix — Implementation Plan (PR breakdown)

Maps the FIX roadmap (#406–#411) onto concrete PRs in dependency order.
Five code PRs plus a tracking comment on the umbrella issue (#408).

Dependency order: #406 → {#407, #409, #410} → #411.

---

## PR 1 — nexus-fix-codec: core scanning & encoding primitives (closes #406)

**Scope.** Leaf crate, std only, no alloc. Runtime primitives every generated
codec builds on:

- `FieldSpan { offset: u32, len: u32 }`, `GroupSpan { offset: u32, count: u16 }`
- `find_soh` / `find_eq` — SSE2 baseline (16B/iter), AVX2 (32B/iter), scalar
  tail, runtime feature detection
- `checksum` / `validate_checksum` — PSADBW byte-sum, 7-byte `10=` trailer
- `parse_tag` — ASCII multiply-accumulate
- `encode_field`, `frame_message`, `header_len` — outbound primitives
- `find_tag` — linear tag scan within a byte range (used by generated group
  entries)
- `DecodeError`, `ChecksumError` — hand-rolled Display/Error, no thiserror

**Design.** SIMD behind `#[target_feature]` fns with SAFETY comments; runtime
`is_x86_feature_detected!`. Scalar path keeps it correct off x86_64. `find_tag`
is on the public surface because the design doc's generated group-entry
accessors call it.

**Out of scope.** Flyweight decoders, groups, watermark scan — all generated by
#407.

**Open questions.**
1. `FieldSpan` accessor naming: doc shows `is_present()` / `slice()`; keep those
   plus `EMPTY`, or rename to `is_empty()`?
2. `frame_message` reserve-ahead vs encoder-owns-buffer. Reserve-ahead (via
   `header_len()`) avoids a memmove — preferred unless you want the simpler API.
3. Bench target: confirm `< 100ns` SOH+checksum measured on the pinned-core /
   turbo-off setup from nexus-shm.

## PR 2 — nexus-fix-codegen: dictionary-driven generator (closes #407)

**Scope.** Standalone bin + lib. Reads QuickFIX XML, writes readable `.rs`:

- `fields.rs` — `TAG_*` consts, typed enums with `from_byte` / `as_byte`
- `messages.rs` — per-msgtype flyweight decoder, `Cell<FieldSpan>` slots +
  `Cell<u32>` watermark, progressive scan, `match`-on-tag dispatch
- `groups.rs` — group iterators + entry decoders
- `encoders.rs` — consume-self builders, `finish() -> usize`
- `mod.rs` — re-exports, MsgType dispatch
- CLI (`clap`) + `generate().out_dir().run()` build.rs API

**Design.** Dictionary-driven, not version-driven. Unknown tags: silent skip.
No encoder validation. DATA fields (95/96, 90/91, 212/213, 348/349, 358/359):
emit length-delimited consume, never `find_soh` inside the value. Watermark
"absent" = scanned to end-of-message and not cached.

**Multi-char enums (from #407 comment).** `SecurityType` (CS/FUT/OPT),
`MsgType` (multi-byte) etc. can't be `#[repr(u8)]`. Generator detects enum
value width and emits `from_bytes(&[u8]) -> Option<Self>` /
`as_bytes(self) -> &'static [u8]` for multi-char, keeps the `u8` form for
single-char. **Confirm this shape.**

**Open questions.**
1. XML parser: `quick-xml` (pull, fast) vs `roxmltree` (DOM, simpler). Lean
   `quick-xml`.
2. rustfmt the emitted files as a post-step, or emit pre-formatted? Affects
   whether `rustfmt` is a runtime dep of the CLI.
3. Component/group nesting depth — cap or fully recursive? Real dictionaries
   rarely exceed 2.

**Depends on** PR 1 (#406).

## PR 3 — nexus-fix-engine: session state machine (closes #409)

**Scope.** Sans-IO, no sockets/async/runtime, time injected.
`Disconnected → LogonSent → Active ↔ Resending → LogoutPending → Disconnected`.
Admin handled internally (Logon/Logout, Heartbeat/TestRequest,
ResendRequest/SequenceReset, Reject); app messages surface as `Copy` events.
Caller-owned encode buffer, zero alloc.

```
handle_message(msg, now) -> queue events
handle_timeout(now)      -> queue timer events
poll_event()             -> drain
encode_pending(kind, buf)-> write into caller buffer
```

**Design — timer (doc's open question).** Session owns timer *state* but never
reads a clock. `handle_timeout(now)` is the only driver; session exposes
`next_deadline()` so the caller's timer wheel knows when to call back.
Decouples from any time source, stays sans-IO. **This is the call I'd make —
confirm.**

**Sequence mgmt.** In/out seqnum tracking, gap detection → ResendRequest,
SequenceReset-GapFill for admin during resend.

**Open questions.**
1. `now` type — raw `u64` nanos (engine-agnostic) vs a nexus-timer type. Raw
   avoids coupling.
2. Session multiplexing (doc Q): out of scope here, one session per connection.
   Agree?
3. Event buffer: fixed capacity (drop/backpressure) or
   caller-drained-before-next-call invariant.

**Depends on** PR 1 (#406).

## PR 4 — nexus-fix-engine: TCP framing (closes #410)

**Scope.** Sans-IO framer, `&[u8]` chunks → framed messages. Scan `8=`, parse
BodyLength(9), take exactly BodyLength + trailer(10), validate checksum, hand
up.

```rust
pub fn decode<'a>(&mut self, buf: &'a [u8])
    -> Result<(Option<&'a [u8]>, usize), FrameError>;
```

**Design — placement (doc's open question).** Framer lives in the **engine**,
using codec primitives (`parse_tag`, `validate_checksum`) — only meaningful in
a streaming context. Keeps the codec a pure leaf.

**DoS bound (from #410 comment).** BodyLength(9) is attacker-controlled.
Without a cap, a forged large `9=` makes the framer buffer unboundedly =
memory-exhaustion DoS. Framer takes a `max_message_len`; over-limit →
`FrameError::Oversize`, before any buffering. The bound lives in the transport
layer, *before* the session FSM sees the bytes. **Confirm the cap belongs
here, not in the session.**

**Open questions.**
1. Partial-message buffering: framer owns a reassembly buffer, or returns
   `consumed` and the caller re-feeds? Latter keeps it allocation-free —
   preferred.
2. Resync on garbage: scan forward to next `8=FIX` vs hard error. Production
   FIX usually resyncs.

**Depends on** PR 1 (#406).

## PR 5 — nexus-fix-engine: persistence traits + ShmJournal impl (closes #411)

**Scope.** `MessageStore` / `SessionStore` traits + default impl over
nexus-shm's ShmJournal.

```rust
trait MessageStore { fn store(...); fn retrieve(...) -> impl Iterator; }
trait SessionStore { fn load(...); fn save(...); }
```

**Blocker.** Default impl needs **ShmJournal (#391), not built yet.** Two ways
to ship:

- **(a)** This PR = traits only + an in-memory test impl; ShmJournal impl
  follows once #391 lands.
- **(b)** Hold until #391 merges, ship traits + ShmJournal together.

Lean **(a)** — unblocks #409/#410 integration against the trait without
waiting on #391. **Your call.**

**Design — resend correctness (from #411 comment).** Resend replays *outbound*
messages, so `store` must tag `Direction`. Preserve admin/app distinction:
admin gaps → SequenceReset-GapFill, app messages → replay with PossDupFlag.
The store keeps raw bytes + direction + seqnum; the session decides replay
semantics.

**Open questions.**
1. `retrieve` returning `impl Iterator` in a trait (RPITIT, fine on MSRV 1.94)
   vs an assoc-type iterator — RPITIT is cleaner.
2. `SessionState` persistence granularity: every seqnum bump (durable, slower)
   vs checkpointed. Target says store write < 500ns → durable per-message is
   the point of ShmJournal.

**Depends on** PR 1 (#406), PR 3 (#409), and #391 (ShmJournal).
